# Клиентская страница, наличные и синхронизация

Клиент (роль 1) открывает каталог с категориями из базы, поиском, сортировкой,
корзиной и оформлением. Гость просматривает каталог, но оформление требует входа.
«Мои заказы» запрашивает только заказы текущего пользователя. Проверка владельца
выполняется сервисом, а идентификатор клиента не принимается из формы.

Пункт выдачи один, согласно заданию: №1, г. Таганрог, ул. Чехова, 336.
Он задан константами ClientOrderService.PickupName/PickupAddress и показан
при оформлении. Схема базы не менялась: отдельной таблицы пунктов выдачи и
исторического адреса в заказе нет. Расписание, карта и дополнительные адреса
не выдумывались.

## Оформление

Доступна только оплата наличными при получении. Окно подтверждения показывает сумму
и пункт выдачи. Заказ записывается с Payment = «Наличные», статусом «Новый» и талоном.
Проверка текущих цен, остатков и резервирование проходят в одной транзакции.
Повторное подтверждение с тем же ключом возвращает уже созданный заказ.

Цена Product.Price считается фактической, OldPrice — прежней. Скидка в сводке
равна разнице с прежними ценами; из фактической суммы она второй раз не вычитается.

## Телефоны и обновления

PhoneNumber.Format отвечает только за отображение: +7 (XXX) XXX-XX-XX.
Префикс +7 в форме фиксирован, вводится десять цифр. Сохранение и проверка БД
сохраняют прежний формат с 8, существующие номера массово не переписываются.

LiveDataWatcher проверяет изменения примерно раз в секунду. Для текущего процесса
DataChanges.Notify вызывается сразу после commit. Для других экземпляров приложения
используется контрольная сумма содержимого таблиц без изменения схемы SQL Server.
Изображения хэшируются на сервере, а не скачиваются каждую секунду. Клиентский
наблюдатель читает только каталог, свои заказы и свою учётную запись; рабочий
наблюдатель учитывает данные разделов менеджера. Это опрос, а не серверный push;
задержка включает интервал опроса и время запроса.

При успешном чтении без изменений списки не перерисовываются. Изменившиеся данные
подхватываются без кнопок «Обновить». При открытом выпадающем меню обновление
откладывается, чтобы оно не закрывалось под курсором. Фильтры, страница списка и
выделение сохраняются. Поля редактора с несохранёнными изменениями не заменяются:
при внешнем изменении записи показано предупреждение, а контроль версии при
сохранении предотвращает перезапись. При потере связи выполняются новые попытки,
наблюдатель останавливается при уходе со страницы.

Уведомления об успешном сохранении/оформлении скрываются через три секунды.
Предупреждение о недоступных товарах в корзине сохраняется до исправления состава.
Кнопки действий в таблицах получили достаточную ширину для отступов, а телефоны —
более широкие столбцы. Кнопка действий сохраняет видимую рамку клавиатурного фокуса
без обрезанного стандартного пунктирного контура.

## Проверки

После сборки Debug:

```powershell
powershell -STA -File Tests/ClientUiChecks.ps1
powershell -STA -File Tests/ManagementUiChecks.ps1
powershell -File Tests/Run-CheckoutChecks.ps1 -Database
powershell -File Tests/Run-LiveUiChecks.ps1 -Database
```

Первые два скрипта работают на данных в памяти и сохраняют PNG-превью в bin.
Проверка Checkout создаёт помеченные временные записи и удаляет их после выполнения. Она проверяет
успешную оплату, отказ/отмену, отсутствие подтверждения, наличие, изменение цены,
повторное подтверждение, изоляцию заказов, неизменность формата телефона в базе,
локальные события и обнаружение изменения поля при прежнем числе записей.

LiveUi запускает скрытое тестовое окно с одним временным товаром: записывает
изменение напрямую через EF без локального события и проверяет, что оно появляется
в интерфейсе по опросу. Дополнительно проверяются сохранение введённого текста,
фильтров, защита устаревшего черновика, обновление кэша при возврате с главной и
скрытие уведомления. После проверки временные товар и категория удаляются.
